# 前沿终端优化计划

> 制定日期：2026-11-04。状态：执行中，进度与验证见 [执行记录](optimization-progress.md)；本计划的指标是拟定验收门槛，不是当前实测成绩。
> 依据：[差距评估](terminal-gap-analysis.md)、[当前能力与缺口](plan.md#11-当前能力与已知缺口)、[ADR](adr/README.md)。
> 本文维护下一阶段执行顺序与验收标准；`plan.md` §11 维护现状；[roadmap.md](roadmap.md) 保留上一轮历史计划。

## 1. 做到什么程度算完成

目标是一个可长期作为主力的 macOS/Linux 原生终端，同时把本机/远端会话保持和 agent 收件箱做成完整体验。
对照 Ghostty/Kitty 的文字与输入、WezTerm 的会话保持、Warp 的命令输出操作、cmux 的任务发现与定位。
不以功能数量或只跑 `cat` 的吞吐量判断是否达到目标。

设置两个交付门槛：

- **主力版本**：文本/复制正确，常用 TUI 输入正常，搜索/链接/剪贴板可用，agent 请求不会丢失或误确认，
  macOS/Linux 都完成日常工作流程，SSH 断线可恢复，有可安装的可信产物。
- **前沿版本**：在主力版本基础上，具备完整字素处理、现代键盘与同步更新、图像显示、命令输出导航、
  可配置操作、受控自动化、无障碍与固定硬件上的性能/功耗验收。

现有约束继续生效：核心 portable、VT/OSC/协议语义单点实现、Rust API 与 C ABI 同步、宿主拥有 PTY、
状态只来自 OSC 7501、系统 SSH、不修改用户 shell 配置、远端宿主单文件 ≤8 MiB。
Windows、内置模型服务、嵌入浏览器、插件市场、云协作不进入本轮必交范围。
机器重启后恢复原进程也不属于当前会话保持承诺；若另做布局/历史恢复，需独立设计并明确语义。

## 2. 阶段、依赖与交付

以下 S0–S7 是本计划的执行阶段，不替代已有 M0–M6 里程碑。
阶段完成必须有证据，不能只按实现文件存在打勾。
`7dd459a` 的 GitHub CI 已全部通过，后续组合字符切片见执行记录；视觉/长期负载验收仍单独记录。

| 阶段 | 交付目标 | 主要依赖 | 完成标志 |
|---|---|---|---|
| S0 | 建立可复现基线与发布检查 | 无 | 固定环境、测试与基准可以复跑 |
| S1 | 修复正确性与会话契约 | S0 | 状态、TERM、确认、握手/尺寸等关键路径有回归保护 |
| S2 | 完整文本模型与两端渲染 | S0；与 S1 的独立修复可交错推进 | 组合字符不丢、宽度一致、复制保留逻辑行、重连不漂移 |
| S3 | 日常终端能力与配置 | 文本相关依赖 S2；部分配置/输入可提前 | 搜索、跨历史选择、链接、剪贴板、现代键盘、配置闭环 |
| S4 | agent 与远端体验 | S1；部分操作依赖 S3 | 接入、通知、准确跳转、断线恢复完整可用 |
| S5 | Linux 功能对齐 | S0 起持续推进，随 S1–S4 接能力 | 同一工作流程在两端成立，GTK CI 和发布包可用 |
| S6 | 现代扩展与持续性能优化 | S2/S3；自动化依赖 S4 | 图像、命令导航、整形、自动化与性能指标达标 |
| S7 | 发布与长期稳定性验收 | 对应版本的前置阶段 | 干净机器可安装/升级，稳定性与平台验收完成 |

主力版本的发布检查使用 S7，在 S1–S5 完成后即可进行；前沿版本增加 S6，再完整复验 S7。
有独立人手时，Linux 日常操作与 CI 可和核心工作并行；单人执行时，每个核心能力做成端到端切片，
尽早由第二客户端消费，不等 macOS 全部完成才接 Linux。

- [x] GTK 客户端加入 Ubuntu CI（构建/clippy/逻辑测试与独立 GL 资源作业已在托管环境通过）：构建、clippy、纯逻辑测试；GUI/IME 另设可重复的桌面验收，不能用编译通过替代。

  空闲/遮挡、内存与 CPU。尚不能支持的负载记录为缺口。
  已有 [宿主协议基线工具](host-benchmark.md)：隔离 release 宿主、原始回显样本、全量重连一致性及最多 16 pane 短时输出；GUI/弱网/持续负载仍待补。
- [ ] VT 语料扩展成文本、属性、光标、模式、换行与重连检查；每个已知问题都有最小复现。
  `vttest` 纳入专项验收；建立协议/OSC/VT 的 fuzz 入口与资源上限断言。
- [ ] 定义发布阻断等级：崩溃/丢文字/误确认/丢会话属于阻断；视觉差异和未承诺扩展分开记录。

**验收**：两平台能按文档复跑；当前失败、忽略、尚未验证项均有解释；基准结果包含原始样本和环境信息。
不要求在此阶段消灭所有缺口，但要能稳定观测后续改动的效果。

- [ ] 明确 shell、前台 agent、OSC 133A 的生命周期；不把“直接子进程退出”宣传成“识别所有 agent 退出”。

- [ ] 随新增现代能力完善专用 terminfo。

## 5. S2：文本模型、协议与渲染

这是后续搜索、复制、连字和图像锚定的基础，优先确定数据语义再优化字形缓存。

- [ ] 定义完整的终端文本模型：主码点及附加码点/字素、格宽与续格、软换行、稳定行标识、历史淘汰边界。
  区分码点保留、字素分段、格宽策略与字形整形，不能只加一个字符串字段便宣称全部支持。
- [ ] 实测当前引擎能否提供所需语义：combining、ZWJ、variation selector、肤色、旗帜、CJK、宽字符覆盖、
  resize/reflow、备用屏。可用则保留引擎；若关键语义无法获得，再按 ADR-0002 做有限范围的替代验证。
  评估必须包含 VT 兼容性、两端接口、宿主体积与构建成本，不直接启动全项目重写。
- [ ] 快照、delta、scroll、搜索/复制结果使用一致的文本语义；通过安全 Rust API 与 C ABI 暴露。
  协议字段优先可选追加/能力协商；若需改变 cell 结构或语义，升级协议大版本，明确旧宿主的退化行为。
  C ABI 通过版本/size 管理兼容，禁止静默重解释字段。
- [ ] 两端实现字素级光栅化和 fallback；核心决定文本与格宽，客户端负责字体整形和绘制。
  光标、选区、IME preedit、搜索命中和鼠标坐标与同一格宽模型一致。
- [ ] 保留软换行，使复制合并自动折行、保留用户实际换行；resize、回看、复制与重连共享同一套行语义。

**验收**：`e + U+0301`、ZWJ emoji、旗帜、肤色与 CJK 在输入→快照→编码/解码→增量→重连→复制后保留预期码点；
显示宽度符合固定测试语料；长命令跨窗口自动折行后复制不多出换行。对平台字体外观允许差异，对丢文字不允许。

## 7. S4：agent 收件箱与远端工作流程

- [x] 提供通用 OSC 7501 上报工具、规范版本/支持字段说明、示例和诊断页；区分“能运行程序”与“该程序可上报状态”。
  提供原生上报、用户主动接入、未监控三种清晰结果；不增加 agent 专用状态解析器，也不自动改用户配置。
- [x] 核对所支持的 OSC 7501 revision、记录树/清除、id、上限及可选字段；未知字段安全忽略，支持矩阵与测试同步。仓库未固定上游 revision，指南按当前实现列子集，不声明未验第三方兼容。
- [ ] blocked/done/error 的桌面通知：去重、节流、勿扰设置、焦点抑制、点击定位真实 host/session/pane。
  通知是提醒，不等于 ack；多窗口避免重复投递，断线后状态明确标注为旧信息。
- [ ] 收件箱筛选、待处理列表、按需展开 pane/记录、键盘切换；未读与 needs-you 口径在两端一致。
- [ ] SSH 睡眠唤醒、网络切换、半开连接、主机不可达、代理进程退出、宿主重启有明确恢复路径。
  短断连优先增量续传，超出 backlog 使用快照；A/B 恢复失败不静默切到不持久的 C。
- [ ] 完成安装控制、版本/能力不兼容提示、可诊断的远端日志；发布的宿主产物要有可验证的签名/完整性链。
  旧宿主有活跃任务时不强制替换进程，新能力缺失明确说明，不破坏既有会话。
- [ ] C 档 resize 通过宿主侧的 PTY/SSH 桥解决，复用 `portable-pty`；不在 Swift/GTK 客户端增加 PTY 操作。
  本地桥可保持本地进程管理，但不宣称 C 档获得了远端持久化。

**验收**：至少三台机器、多会话、多 pane 混合状态可准确找到待处理项；重复/乱序/重连不误确认。
30s 与 5min 断连恢复原远端任务和正确画面；宿主重启明确告诉用户旧任务已丢失，不显示为恢复成功。
用户能按公开文档完成上报接入与远端安装，不依赖开发者手改环境。

## 9. S6：现代扩展、性能与可编程性

### 扩展能力

- [ ] 两端编程连字与可控字体特性：macOS ASCII 标点段连字及 `font-ligatures` 已从远端合入；Linux 与完整字素整形待补，继续验证格宽/选区。
- [ ] Kitty graphics protocol：明确支持子集、查询应答、图像与格子的锚定、滚动/删除/resize/重连和备用屏规则。
  宿主维护有限额的图像对象与协议语义，客户端解码/绘制；不能让某个客户端持有唯一图像状态。
  大对象按现有单帧上限分段，并控制解码后尺寸/内存；仍须满足宿主体积、依赖许可和无 GUI 依赖约束。
  Sixel/iTerm 图片等后续兼容协议按实际工作负载决定，不为“支持更多”牺牲核心稳定性。
- [ ] 完善命令输出块：跳转、复制、折叠/过滤的可行性、退出码与长输出查找；基于显式 shell 标记，不从屏幕反推命令。
- [ ] 面向用户的 CLI：列出/创建/附加会话、分屏、聚焦、发送明确输入、读取状态；复用现有核心协议。
  自动化是正式产品接口，只允许当前用户、不开任意 shell 调试端口；命令版本、失败语义和权限可解释。
  GUI 专属动作需要独立客户端入口时先写设计，不把 UI 指令塞进宿主。

### 性能优化

- [ ] 通过剖析定位解析、转换、CBOR、队列、网络、主线程、字形缓存、GPU 和呈现各阶段耗时。
- [ ] 优先处理无用整屏转换、重复拷贝/编码、滚动行复用、图集失效和后台任务；性能改动必须保留正确性语料。
- [ ] 评估远端帧编码与 zstd 的净收益；仅在带宽/CPU/时延基准改善时启用协商压缩。
- [ ] Linux 确有主线程绘制瓶颈时再按 ADR-0011 引入后台线程/DMABUF；保持原生控件与输入流畅。
- [ ] 调整帧调度以支持 60/120Hz，核对同步更新、光标动画与遮挡；高输出时允许合并屏幕帧，但不能丢状态或输入。

**验收**：图像/TUI/文字混合场景重连不丢内容；自动化与人工操作结果一致；下节性能门槛在参考机上有可复跑结果。

## 10. 性能和稳定性门槛

以下是建议的初始目标。S0 先验证测量手段、噪声与参考机，随后冻结环境和门槛；任何调整都说明原因，不能为通过测试随意放宽。

| 项目 | 测量方式 | 初始验收目标 |
|---|---|---|
| 本地输入回显 | 按键注入到对应内容呈现，固定 shell/刷新率，记录 p50/p95/p99；硬件呈现无法测量时明确只是软件链路 | p95 ≤ 两个刷新周期 + 5ms；持续输出时 p99 ≤ 100ms |
| 渲染预算 | 固定网格/字体/分屏负载，分别记录 CPU 构帧、GPU、呈现与丢帧 | 60Hz 的 p99 构帧与 GPU 单阶段各低于 16.7ms；120Hz 档各低于 8.3ms，并验证实际呈现不卡顿 |
| 多 pane | 16 pane × 每 pane 1MB/s，持续 10min，同时输入/切换/滚动 | 无崩溃、输入/状态不丢，UI 不持续冻结；停止输出后及时追到最终画面，队列和内存有界 |
| 大历史 | 100,000 行，固定平均行长与 Unicode 混合语料，搜索可取消 | 本地搜索首批结果 p95 ≤ 100ms；回看不随历史总行数线性变慢，界面不被索引阻塞 |
| SSH | RTT 50/100/200ms、限速、丢包/断链；分别测输入与恢复 | 无丢输入/错屏/错状态；健康链路下输入软件开销 p95 ≤ RTT + 50ms，故障恢复另测，不混为一项 |
| 内存 | 记录每 pane、每格、历史、图像与队列成本；8h soak 后回到同等负载 | 排除有上限缓存预热后，无持续增长；每条队列与缓存都有上限及超限行为 |
| 空闲与遮挡 | shell 安静，分别关闭光标/状态动画及保留默认动画 | 无动画时无无意义连续重绘，单窗口客户端空闲 CPU 平均目标 <1% 单核；默认动画与功耗单独报告 |
| 会话保持 | 杀客户端、关窗口、网络断开、重连、宿主换 instance | 客户端故障不杀 pane；同宿主恢复画面/状态；宿主退出不冒充恢复原任务 |
| 宿主发布体积 | 各远端目标 release 产物，含新增协议能力 | 未压缩二进制 ≤8 MiB，Linux 保持静态单文件 |

比较 Ghostty/Kitty 时固定版本、字体、网格、刷新率、构建模式与前台状态；同负载重复测量，并报告噪声。
与 WezTerm 等比较远端 mux 才有对应意义；不能把本机无 mux 与 SSH mux 的总时延直接作优劣排名。
