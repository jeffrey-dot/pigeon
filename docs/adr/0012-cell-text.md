# ADR-0012：保留单元格附加文本，兼容既有 cell 编码

- 状态：已采纳
- 日期：2026-11-04
- 依据：[优化计划 S2](../optimization-plan.md)、[协议](../protocol.md)

## 决定

第一片解决 Alacritty cell 的零宽附加码点在转换时丢失的问题，不改变引擎现有格宽和跨格字素规则。

- 核心 cell 保留完整 UTF-8 文本；普通单码点 cell 不额外分配文本，附加内容随快照/delta/回看移动。
- 线上 cell 仍是原来的 4/5 整数数组；快照/delta 增加可省略的 `text` 稀疏表，项为 `{row:i32, col:u16, text:str}`。
  非负 row 是屏幕行；快照中的负数从历史末尾倒数（-1 为最新历史行）。delta 只允许覆盖本帧替换的行。
  未列出的 cell 只有原码点；收到新快照或行替换时旧附加内容随之被替换，不能残留。
- text 含主码点及附加码点。接收端校验坐标、重复项、首码点一致、无控制字符及单 cell 4096 UTF-8 字节上限。
  导出超过上限时在码点边界截断附加部分；这只是快照边界的上限，不声称引擎内部内存已完整受控。
- C ABI 不改变 `PgCell` 数组步长；在 `PgSnapshot` / `PgDelta` 尾部追加稀疏文本表，字符串随所属快照释放。
  安全 Rust API 从同一转换返回完整 cell 文本；旧客户端忽略新增字段、继续显示主码点。
- 协议仍为 1.0 的可选字段扩展，不给已有字段新含义；旧宿主没有 text 时新客户端维持原行为。

## 约束

- 历史帧预算和增量 backlog 计费包括附加文本，不能让新增字符串绕过资源上限。
- macOS 使用 CoreText 整形 cell 文本；Linux 使用 swash 整形，位置仍被核心格宽约束。
- `👩‍💻` 等跨多个宽 cell 的整簇重排不是这片的完成承诺；先确保码点不丢，后续独立解决整簇宽度。
- 本决策不改变字体/图像依赖只在客户端的分层。

## 验收

分解重音经嵌入 API、快照/增量往返、历史、C ABI、客户端缓存和复制后保留；普通字符覆盖原格后附加文本消失。
旧消息仍能解码，畸形坐标/重复项/控制字符拒绝；macOS/GTK 整形各有测试和实际平台验证记录。
